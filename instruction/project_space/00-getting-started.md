# 进入、创建与认识项目空间

本章从还没有进入任何空间开始，说明怎样找到空间、创建空间，以及进入空间后公共区域中的信息。

## 1. 项目空间列表

进入“项目空间”后，左侧列表提供以下内容：

1. 当前用户可访问的空间总数。
2. “+”按钮，用于新建项目空间。
3. 按空间名称或编码搜索。
4. “最近空间”，优先按本机最近访问记录排列，再参考空间更新时间。
5. 每个空间的名称、编码、状态和成员数；名称与编码在同一行，状态用圆点表示，成员数紧随圆点之后。

点击一个空间后，默认进入“概览”。

常见页面状态：

| 状态 | 页面表现 | 建议操作 |
| --- | --- | --- |
| 正在加载 | 显示骨架屏 | 等待加载完成 |
| 没有可访问空间 | 显示“暂无项目空间” | 有权限时创建第一个空间，或请管理员邀请 |
| 空间不存在或无权访问 | 不加载空间内容 | 返回列表并确认链接、成员关系和空间状态 |
| 加载失败 | 显示失败提示 | 使用“重试” |

## 2. 新建项目空间

只有拥有相应创建能力的用户会看到新建入口。

### 2.1 选择起步方式

创建窗口先要求选择一种起步方式。

#### 空白空间

适合希望从基础模型开始配置的团队。

- 新空间保留平台基础任务模板。
- 不会自动完成字段、流程和权限的业务化配置。
- 创建后进入“设置 → 管理首页”。

#### 场景模板

可选：

- 研发协作
- 市场项目
- HR 事务
- 交付管理

这里的选择只记录新手引导意图，不会在创建空间时自动安装或发布模板。创建完成后会进入“设置 → 场景模板”，管理员仍需预检、安装，并检查各组件是否符合团队实际情况。

#### 克隆配置

选择一个当前用户可访问的参考空间，用于进入克隆预检路径。

当前版本的“克隆配置”不会直接复制：

- 成员及其角色
- 工作项数据
- 附件
- 权限快照

它目前创建的是一个空白空间并进入“设置 → 工作模型”进行预检，不能把它理解为完整空间复制。

### 2.2 填写空间资料

| 字段 | 是否必填 | 规则与作用 |
| --- | --- | --- |
| 空间名称 | 是 | 最多 128 个字符，面向成员显示 |
| 空间编码 | 否 | 小写字母、数字和连字符，最多 64 个字符；留空时由系统生成 |
| 可见性 | 是 | `private` 仅成员可见；`workspace` 允许工作区内发现空间元数据 |
| 说明 | 否 | 最多 2,000 个字符，用于说明范围、目标和边界 |

建议在说明中至少写明：空间负责的业务范围、哪些团队参与、哪些内容不应放入该空间。

### 2.3 创建后的第一步

不同起步方式会把你带到不同入口：

| 起步方式 | 创建后入口 | 接下来做什么 |
| --- | --- | --- |
| 空白空间 | 设置 → 管理首页 | 按配置待办依次完成成员、模型和发布 |
| 场景模板 | 设置 → 场景模板 | 预检并安装所选场景，再逐项检查配置 |
| 克隆配置 | 设置 → 工作模型 | 核对参考空间和本空间差异，手动完成配置 |

## 3. 空间公共头部

进入空间后，所有主 Tab 共用顶部信息区：

- 空间名称
- 空间状态
- 当前空间角色
- 空间编码
- 空间说明
- 成员数
- 可见性
- 最后更新时间

这些信息帮助你先确认“我现在在哪个空间、以什么身份操作、空间是否允许写入”。

### 3.1 简洁模式与高级模式

在增强体验已开启且服务端允许时，owner/admin 可以切换显示偏好：

- 简洁模式：减少解释密度，适合熟悉流程后的日常操作。
- 高级模式：显示更多说明和管理入口，适合配置和排查。
- 恢复默认：恢复为简洁模式。

显示模式只影响信息密度，不会增加或减少权限。离线时不能切换或重置。

### 3.2 成员视图预览

owner/admin 可使用“成员视图预览”查看 member 或 guest 会看到哪些导航入口。

它只预览导航元数据：

- 不加载对方能看到的工作项。
- 不加载成员、配置或指标数据。
- 不模拟对方身份。
- 不改变当前用户权限。

因此它适合检查信息架构，不等于完整的权限验收。真正的字段和动作权限还要在测试工作项中核对。

### 3.3 使用引导

增强体验启用并且当前用户是空间成员时，公共头部可能提供使用引导。它帮助定位入口，但不会自动替你安装模板、发布配置或创建数据。

## 4. 角色决定入口，策略决定具体动作

当前空间角色有四种：

| 角色 | 典型定位 | 标准入口 |
| --- | --- | --- |
| owner | 空间最终负责人，包含危险操作 | 全部 5 个主 Tab |
| admin | 日常空间管理员 | 全部 5 个主 Tab |
| member | 执行和协作成员 | 概览、工作项 |
| guest | 受限协作者 | 概览、工作项，通常只读 |

需要区分两层控制：

1. 空间角色及服务端能力决定某个主 Tab 是否出现。
2. 已发布的数据权限策略、事项角色、字段权限和当前状态决定进入页面后具体能做什么。

例如，member 能进入“工作项”，不代表能编辑每条事项；guest 能看到“工作项”，也不代表能读取每个字段。

非成员在 `workspace` 可见空间中只能看到最小空间元数据。企业管理员如果不是该空间成员，也不会自动获得空间内容旁路；企业级审计应在企业治理后台进行。

## 5. 空间状态

| 状态 | 含义 | 使用影响 |
| --- | --- | --- |
| `active` | 正常使用 | 在权限允许时可配置、创建和修改 |
| `disabled` | 暂停使用 | 关闭写入和成员变更，内容只读保留 |
| `archived` | 历史归档 | 作为历史记录只读保留 |

停用或归档不会删除历史数据。owner/admin 可从提示条进入设置恢复；普通成员需要联系 owner/admin。

## 6. 子 Tab 的通用导航行为

页面用 URL 中的 `panel` 参数记录当前子 Tab：

- 链接中的 Tab 有效且当前用户可见时，直接打开该 Tab。
- 参数无效或无权访问时，回到第一个可见 Tab。
- 切换子 Tab 不会为浏览器历史增加一条记录。
- 离开后未保存的组件内输入可能丢失；正式配置应先点击保存。

直接打开无权访问的主 Tab 或子 Tab 不会绕过权限，页面也不会偷偷加载其数据。

## 7. 第一次进入的检查清单

owner/admin 建议先完成：

1. 核对空间名称、编码、说明和可见性。
2. 邀请至少一名 member，并确认谁是 owner/admin。
3. 明确要使用哪些任务模板。
4. 为每个模板配置字段和 create/detail 布局。
5. 配置流程、关系和数据权限。
6. 校验并发布配置。
7. 创建一条测试事项，以不同角色核对结果。

普通成员第一次进入时建议：

1. 在公共头部确认自己的角色和空间状态。
2. 从“概览 → 我的工作”查看待办。
3. 从“概览 → 可用工作项”确认可创建的事项类型。
4. 在工作项详情的“权限”中查看具体动作和字段访问。
