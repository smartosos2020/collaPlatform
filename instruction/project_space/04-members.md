# 主 Tab：成员

“成员”用于管理谁属于空间以及他们承担什么空间角色。当前正常导航只对 owner/admin 显示。

子 Tab 顺序：

1. 空间成员
2. 成员邀请

成员角色会影响主导航和管理能力；事项中的 creator、assignee、collaborator、watcher 则是另一层“事项角色”，不要混淆。

## 1. 空间成员

### 1.1 成员表格

按行显示：

- 头像
- 显示名
- 邮箱或账号
- 空间角色
- 账号状态
- 加入时间
- 可用操作

顶部提供“直接加入”和“邀请成员”。

### 1.2 候选人搜索

直接加入和邀请都从同一企业的候选用户中选择。可以按名称、账号或邮箱搜索，候选人必须：

- 账号已启用。
- 还不是当前空间的有效成员。
- 属于同一企业。

单次最多返回 50 人。

### 1.3 直接加入

1. 点击“直接加入”。
2. 搜索并选择企业用户。
3. 选择空间角色。
4. 点击“加入空间”。

加入成功后立即出现在成员表中，并按角色获得空间入口和能力。

### 1.4 邀请成员

1. 点击“邀请成员”。
2. 选择候选人和角色。
3. 选择有效期：24 小时、3 天或 7 天。
4. 点击“发送邀请”。
5. 到“成员邀请”查看状态。

邀请在被接受前不会让用户成为有效空间成员。

### 1.5 可分配角色

| 操作者 | 可以通过普通角色下拉分配 |
| --- | --- |
| owner | admin、member、guest |
| admin | member、guest |

owner 不能通过普通下拉赋予，必须使用“转为 Owner”。当前角色含义：

- owner：空间最终负责人，可以转移所有权和执行危险操作。
- admin：日常空间管理员。
- member：普通执行成员。
- guest：受限协作者。

### 1.6 调整角色、转移 Owner、移除

行级动作：

- 调整非 owner 的角色。
- owner 把另一位成员“转为 Owner”。
- 移除非 owner、非当前登录用户的成员。

转移所有权后：

- 目标成员成为 owner。
- 原 owner 变为 admin。

移除成员后：

- 对方立即失去空间访问。
- 操作写入审计和事件。
- 最后一个 owner 不能被移除。

### 1.7 权限和空间状态

- 底层成员列表允许有效空间成员读取，但当前 UI 的“成员”主 Tab只给 owner/admin。
- 搜索、加入、邀请、调角色、移除需要 owner/admin。
- 所有成员治理写入要求空间为 active。
- owner 只能由当前 owner 转移。
- admin 不能修改或移除另一个 admin，也不能处理 owner。
- disabled、archived 时成员页只读。

### 1.8 当前边界

- 前端会对所有非 owner 行显示角色下拉和移除；admin 操作另一位 admin 时才由服务端拒绝。
- 虽然页面读取了角色 capability，角色下拉仍由前端硬编码。
- 不支持按部门或用户组批量加入。
- 没有成员分页、筛选或实际 capability 明细。
- 账号已停用但成员关系仍 active 的记录可能继续显示，部分操作会被服务端拒绝。

## 2. 成员邀请

### 2.1 邀请表格

显示：

- 受邀成员
- 邮箱或用户 ID
- 目标角色
- 状态
- 有效期至
- 操作

邀请状态：

| 状态 | 含义 |
| --- | --- |
| 待接受 | 邀请仍有效，等待收件人处理 |
| 已接受 | 用户已成为空间成员 |
| 已拒绝 | 收件人拒绝 |
| 已撤销 | 管理员撤销 |
| 已过期 | 超过有效期 |

### 2.2 重发和撤销

只有 pending 邀请显示：

- 重发：重新生成令牌并按默认有效期续期。
- 撤销：使邀请失效并保留历史。

当前重发不能重新选择有效期。邀请接受后，用户出现在“空间成员”列表；拒绝、撤销和过期记录继续作为治理历史保留。

### 2.3 退出空间

页面还提供“退出空间”：

1. 点击退出。
2. 确认。
3. 当前用户被移出空间并返回项目空间列表。

之后若要重新进入，需要管理员再次直接加入或邀请。最后一个 owner 不能直接退出，必须先在“空间成员”转移所有权。

### 2.4 权限与当前闭环缺口

- 邀请列表、重发、撤销要求 owner/admin。
- 重发要求 active；只有 pending 邀请可重发或撤销。
- 接受邀请要求空间 active 且邀请未过期。
- 底层允许任何有效成员退出，但 member/guest 看不到“成员”主 Tab，因此没有可见退出入口。
- owner 的退出按钮没有提前禁用，点击后才由服务端提示必须转移所有权。
- 表格每页 5 条，没有状态筛选。

最重要的当前缺口是：服务端虽然提供接受和拒绝邀请接口，但项目空间 Web 端没有收件人的“接受/拒绝邀请”页面。因此，仅靠当前项目空间页面还不能完成邀请收件人闭环；需要通过其他已接入入口或管理员直接加入。

## 3. 成员与其他功能的关系

```text
空间成员与空间角色
  ├─ 决定概览/工作项/项目管理/成员/设置的主导航
  ├─ 为保存视图分享提供目标成员
  ├─ 为工作项参与者提供候选人
  ├─ 为资源分配提供成员
  ├─ 为交付会签提供必签人
  └─ 作为数据权限策略中的 space_role 主体

事项参与者
  ├─ creator
  ├─ assignee
  ├─ collaborator
  └─ watcher
```

空间成员只是进入空间的身份。是否能查看某条事项、编辑某个字段、执行某个流程动作，还要继续经过已发布数据权限策略、事项角色和字段访问策略判断。

## 4. 推荐管理顺序

1. 确保空间至少有一位明确 owner。
2. 只给需要配置和治理的人 admin。
3. 日常执行者使用 member，外部或受限协作者使用 guest。
4. 用直接加入完成内部确定成员；只有接收闭环可用时再使用邀请。
5. 发布工作模型后，用 member/guest 测试工作项和字段权限。
6. 人员离开团队时先处理事项负责人、资源分配和会签责任，再移除成员。
