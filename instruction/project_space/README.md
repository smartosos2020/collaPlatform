# 项目空间使用手册

这套手册面向第一次使用 Colla Platform 项目空间的成员、项目负责人和空间管理员。内容以 2026-08-01 的当前界面和代码为准，严格按照页面中的主 Tab、子 Tab 以及页内区块顺序编排。

## 先建立一个整体认识

项目空间不是一个单独的“项目看板”，而是把配置、执行、协作和治理放在同一边界中的工作容器：

```text
设置：定义团队怎样工作
  ├─ 工作模型：任务模板、字段、表单与详情页
  ├─ 流程与权限：状态、审批、关系、权限并发布版本
  ├─ 自动化与协同：规则、连接器、跨空间授权与同步
  └─ 度量治理：指标、看板、风险和审计报表
                  ↓
成员：决定谁能进入空间、承担什么空间角色
                  ↓
工作项：按已发布配置创建和执行具体事项
                  ↓
项目管理：汇总计划、资源、风险、交付及跨团队结果
                  ↓
概览：把与当前用户有关的待办、可用模板和动态聚合起来
```

这里最容易混淆的几个概念是：

| 概念 | 含义 | 典型结果出现位置 |
| --- | --- | --- |
| 项目空间 | 成员、配置、工作项、项目管理数据共同所属的协作边界 | 整个项目空间 |
| 任务模板/工作项类型 | 一类事项的定义，例如需求、任务、缺陷 | 设置 → 工作模型 |
| 字段 | 一类事项需要记录的数据 | 新建事项和事项详情表单 |
| 页面布局 | 字段在新建页、详情页中的分区、顺序和可见方式 | 工作项 → 新建/事项详情 |
| 配置草稿 | 尚未影响成员使用的编辑中配置 | 设置 → 流程与权限 |
| 已发布配置版本 | 经过校验、不可变、供新工作项绑定的运行版本 | 概览 → 可用工作项；工作项运行时 |
| 工作项 | 按某个已发布模板版本创建的具体事项 | 工作项 |
| 状态流程 | 一次只处于一个状态的轻量生命周期 | 工作项详情 → 状态流程 |
| 节点流程 | 可包含审批、会签、分支、汇聚和任务的协作流程 | 工作项详情 → 审批与协作流程 |
| 数据权限策略 | 决定某个主体在某个数据范围内可执行哪些动作 | 设置 → 流程与权限；工作项详情 → 权限 |
| 项目计划 | 面向项目阶段和里程碑的管理对象，不等于状态流程 | 项目管理 → 项目计划 |

## 主导航与可见范围

项目空间按使用者任务分成三个区域，主 Tab 固定按下列顺序出现：

1. 成员工作区
   1. 概览
   2. 工作项
2. 项目管理
   1. 项目管理
3. 空间管理
   1. 成员
   2. 设置

当前标准角色的入口如下。最终是否显示仍以服务端返回的能力为准。

| 身份 | 概览 | 工作项 | 项目管理 | 成员 | 设置 |
| --- | --- | --- | --- | --- | --- |
| owner | 是 | 是 | 是 | 是 | 是 |
| admin | 是 | 是 | 是 | 是 | 是 |
| member | 是 | 是 | 否 | 否 | 否 |
| guest | 是 | 是，通常为只读 | 否 | 否 | 否 |
| 可发现空间的非成员 | 仅空间元数据 | 否 | 否 | 否 | 否 |
| 非空间成员的企业管理员 | 不获得空间内容旁路 | 否 | 否 | 否 | 否 |

因此，普通成员的常用路径是“概览 → 工作项”；owner/admin 才会看到集中在后面的项目管理和空间管理能力。

## 建议的首次配置顺序

如果你是 owner/admin，不要从页面中随意挑一个入口开始。按以下顺序可以减少返工：

1. 创建空间，确认名称、编码和可见性。
2. 在“成员”中邀请用户并分配空间角色。
3. 在“设置 → 工作模型”选定任务模板，配置字段和 create/detail 页面布局。
4. 在“设置 → 流程与权限”配置数据权限、关系以及状态流或节点流。
5. 先校验草稿，再发布不可变版本。
6. 回到“概览 → 我的工作”，确认模板进入“可用工作项”。
7. 创建测试工作项，分别以管理员、member、guest 检查页面和字段权限。
8. 再按需要配置项目计划、自动化、跨空间协作、指标和风险治理。
9. 正式使用后，通过版本历史、运行记录和治理报表追踪变化。

## 阅读约定

每章尽量回答五个问题：

1. 这块功能解决什么问题。
2. 页面上每个区块和字段有什么作用。
3. 应该按什么顺序操作。
4. 配置完成后到哪里看到结果。
5. 当前版本有哪些边界，避免把尚未实现的能力当成可用能力。

文档中的 `owner`、`admin`、`member`、`guest` 是当前系统的永久角色 key；“任务模板”和代码中的“工作项类型”指同一个概念；“事项”和“工作项”也指同一运行对象。
