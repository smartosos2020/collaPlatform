# 主 Tab：项目管理

“项目管理”把工作项执行之上的计划、资源、风险、交付、跨空间协作和结果治理集中起来。当前正常导航只对空间 owner/admin 显示。

共有 13 个二级入口，统一顺序是：

1. 项目概况
2. 项目计划
3. 人员排期
4. 实际工时
5. 资源产能
6. 资源日程
7. 风险与决策
8. 交付验收
9. 跨空间关系
10. 跨空间同步
11. 跨团队全景
12. 结果指标
13. 指标风险

界面先把前 8 项显示为项目管理页签；后 5 项位于下方“协作与结果”入口区。点击任一入口后会切换到后 5 个页签，并提供“返回项目管理”。本章仍按统一的 13 项顺序说明。

## 共同权限与状态边界

- 当前服务端只给空间 owner/admin 返回项目管理主入口和 `manage_project`。
- 部分底层项目服务允许 active member 读写、guest 只读，但普通成员当前没有项目管理导航入口；不要把底层能力误认为已暴露的成员功能。
- disabled 空间多数项目数据可读但不可写。
- 信息架构把 archived 标为只读可见，但多个计划、资源、台账、交付、跨空间和指标服务会拒绝读取 archived 空间，当前可能出现加载失败。这是现有导航契约与服务行为的差距。

## 1. 项目概况

### 1.1 作用

把项目计划、风险/问题/变更、交付验收聚合成一个项目健康入口。它不创建新的业务事实，只读取其他项目管理页中的事实并派生健康结果。

### 1.2 个人视图

可选择显示：

- 计划
- 台账
- 交付
- 健康

还可以开启紧凑模式、保存个人偏好、输入离线项目笔记，并查看在线/离线状态。

个人偏好只影响当前用户。离线笔记只存在当前组件内存，切换页签或刷新后会丢失，不能作为正式记录。

### 1.3 项目健康

健康状态可能是健康、需关注、严重或未知。页面显示：

- 健康策略版本和派生时间
- 未验证问题数
- 高风险数
- 待决变更数
- 待验收数
- 驳回交付数
- 最多 50 条可解释健康信号
- 每条信号的规则、来源类型和来源版本

当来源达到预算上限时，状态变为 `unknown`，不会把不完整数据误判成健康。

### 1.4 来源摘要

- 计划偏差：完成度、可见里程碑、逾期里程碑。
- 项目台账：当前可见记录数量。
- 交付与验收：当前可见交付物数量。

### 1.5 使用顺序与结果

1. 先在“项目计划”“风险与决策”“交付验收”维护事实。
2. 返回“项目概况”。
3. 点击“REST 校准”。
4. 选择个人需要显示的区块并保存偏好。

阻塞和交付事实还会成为“指标风险”的证据来源。当前健康信号没有直接跳转来源记录的入口。

## 2. 项目计划

### 2.1 作用

管理项目级计划、阶段、里程碑及其与工作项的关联，并计算完成度和逾期情况。

项目计划阶段不等于任务模板的状态流程节点；计划日期也不会自动改写工作项日期。

### 2.2 页面字段和按钮

字段：

- 项目计划选择器
- 计划名称，最多 120 字
- 计划说明，最多 1,000 字
- 开始日期
- 结束日期

按钮：

- 新建计划
- 保存名称与说明
- 发布计划
- 归档计划
- 恢复为草稿

选择已有计划后，起止日期不可编辑，当前只允许保存名称和说明。

### 2.3 新建和状态

新建计划时自动创建一个“交付阶段”和一个“计划交付”里程碑，暂时没有工作项关联。

```text
draft → published
draft/published → archived
archived → draft
```

页面结果包括状态、阶段数、里程碑数、逾期数、当前可见关联数、完成百分比，以及里程碑名称、状态和目标日期。隐藏关联被截断时会提示。

### 2.4 推荐操作

1. 填写名称、说明和日期。
2. 新建计划。
3. 检查自动生成的阶段和里程碑。
4. 发布计划。
5. 不再使用时归档，需要修改时恢复为草稿。

结果会进入“项目概况”的计划偏差；逾期里程碑会成为“指标风险”的 `overdue` 证据。

### 2.5 当前边界

- 页面不能新增、编辑或删除阶段。
- 页面不能新增、编辑、完成里程碑。
- 页面不能把工作项关联到里程碑。
- 已有计划不能修改起止日期。
- 这些高级能力目前主要由接口或其他调用方维护。

## 3. 人员排期

页面标题是“工作日历与估分”。

### 3.1 作用

定义空间工作时间口径，为工作项记录估算，并生成基于工作日历的预计开始和完成时间。

### 3.2 空间工作日历

字段：

- IANA 时区，例如 `Asia/Shanghai`
- 工作周：星期一至星期日多选
- 每日可用分钟：1–1,440
- 例外日期
- 例外可用分钟：0–1,440
- 例外说明

可以添加、移除例外，保存工作日历，并执行“REST 校准”。最多保存 366 个例外日期。

### 3.3 受权事项估分

字段：

- 工作项 UUID
- 估分单位：小时、工作日、故事点
- 估分数值：0.01–100,000

保存后显示工作项 ID、估分、版本和时间投影。

故事点是独立估算单位，不换算为日期；小时和工作日会结合当前日历计算。

### 3.4 使用顺序与结果

1. 配置时区、工作周和每日可用分钟。
2. 添加节假日、调休或部分可用日。
3. 保存工作日历。
4. 输入当前有权查看的工作项 UUID。
5. 选择单位并填写估分。
6. 保存后查看时间投影。

估分会用于“实际工时”的偏差计算；工作日历还被“资源产能”和“资源日程”使用，冲突进一步成为资源风险证据。

### 3.5 当前边界

- 工作项 UUID 需要手工输入，没有选择器。
- 时区为自由文本，没有时区选择器或即时校验。
- 例外日期必须点击“保存工作日历”后才提交。
- 离线资源草稿只在组件内存中，切换或刷新会丢失。
- 页面没有解释估分与具体计划里程碑的对应关系。

## 4. 实际工时

### 4.1 作用

记录工作项实际用时，保留不可变修订历史，并与估分计算偏差。

### 4.2 录入字段

- 工作项 UUID
- 工时日期
- 工时分钟：1–1,440
- 来源：手工、导入、代理
- 修订原因，最多 500 字

### 4.3 状态与动作

- 创建工时草稿。
- `draft` 可提交。
- `submitted` 可撤回，必须填写原因。
- 非 `void` 可作废，必须填写原因。

每条记录显示工作项 ID、日期、分钟、审批状态、聚合版本、修订号、估算/实际/偏差和完整修订历史。列表最多读取 200 条，超过后显示截断提示。

### 4.4 使用顺序与结果

1. 先在“人员排期”给事项配置可比较的估分。
2. 输入事项 UUID、日期、分钟和来源。
3. 创建草稿并检查。
4. 提交。
5. 如需撤回或作废，填写真实原因后操作。

已提交工时进入估算偏差，也进入“资源产能”和“资源日程”的实际用量。

### 4.5 权限和当前边界

active 且不是 guest 才可写。代理他人录入要求 owner/admin 和原因，但当前页面没有代理对象选择，选择“代理”仍会记录为当前用户。

当前还存在：没有编辑草稿入口、没有审批人审批动作、必须手输工作项 UUID、离线草稿不持久化等边界。

## 5. 资源产能

页面标题是“人员负荷与产能冲突”。

### 5.1 作用

把工作项、成员、工作日历和分配比例组合成每日负荷，识别低负荷、满载和超载。

### 5.2 人员分配

字段：

- 工作项 UUID
- 空间成员 User UUID
- 开始日期
- 结束日期
- 分配比例：0.01%–100%
- 调整原因：最多 500 字，必填

按钮：创建人员分配、REST 校准。

### 5.3 负荷窗口

按成员和日期显示：

- 成员 UUID
- 日期
- `underloaded`、`full` 或 `overloaded`
- 是否冲突
- 产能分钟
- 分配分钟
- 已提交实际分钟
- 负荷进度条和解释

分配列表最多读取 200 条。

### 5.4 使用顺序与结果

1. 先配置工作日历。
2. 确认目标用户是有效空间成员。
3. 输入工作项和用户 UUID。
4. 设置日期范围和比例。
5. 填写不可变调整原因。
6. 创建分配并检查冲突。

结果会显示在当前负荷窗口和“资源日程”；超载或冲突会成为“指标风险”的 `resource` 证据。

只有 active owner/admin 可调整。当前只能创建，不能在此更新、结束或归档分配；也没有个人产能规则编辑器、对象选择器或持久化离线草稿。

## 6. 资源日程

页面标题是“人员排期甘特与资源调整”。

### 6.1 作用

把人员分配渲染为按时间的甘特视图，并提供正式调整前的预览。

### 6.2 窗口与缩放

字段：

- 排期窗口开始
- 排期窗口结束
- 缩放：日、周、月

“保存窗口”保存当前用户的个人偏好，“REST 校准”重新获取当前事实。

### 6.3 甘特视图

每个成员一行，显示成员 UUID、冲突数、产能分钟、分配分钟、实际分钟、人员分配时间条和冲突标记。点击时间条可选中对应分配。

### 6.4 调整预览与提交

选择当前受权分配后填写：

- 新开始日期
- 新结束日期
- 新分配比例
- 调整原因

先点击“预览”，确认结果后再“提交调整”。正式提交会更新同一条 canonical allocation。

提交结果会同步反映到“资源产能”，冲突会影响资源风险信号。

### 6.5 当前边界

- 下拉框只显示工作项 UUID 和比例，没有标题或成员名。
- 不能拖拽甘特条。
- 没有结束、归档分配的独立动作。
- 截断后不能继续分页。

## 7. 风险与决策

页面标题是“风险、问题、决策与变更台账”。

### 7.1 作用

集中维护四类人工治理事实：风险、问题、决策、变更。

它与“指标风险”不同：本页保存人工维护的业务台账；“指标风险”根据当前事实自动生成风险信号。

### 7.2 创建和默认内容

填写台账类型、标题（最多 160 字）、摘要（最多 2,000 字）和到期日期。

创建时系统补充：

- 风险：概率 3、影响 3、初始风险分 9。
- 风险和问题：一条默认响应计划。
- 决策：用摘要作为默认决策依据。
- 变更：用摘要作为默认影响说明。
- 负责人为空。

### 7.3 列表与详情

可筛选全部、风险、问题、决策、变更，并执行 REST 校准。列表显示类型、标题、状态；风险额外显示风险分。

详情显示类型、状态、版本、风险概率/影响/风险分、标题、摘要、响应计划、当前可见引用数和不可变状态历史。

### 7.4 状态动作

风险：

```text
identified → 完成评估 → assessed
assessed → 进入监控 → monitoring
monitoring → 关闭风险 → closed
closed → 重新打开 → monitoring
```

问题：

```text
open → 升级问题 → escalated
escalated → 标记解决 → resolved
resolved → 验证完成 → verified
verified → 重新打开 → open
```

决策：

```text
proposed → 采纳决策 → adopted
adopted → 撤销决策 → revoked
```

变更：

```text
proposed → 完成影响分析 → analyzed
analyzed → 拒绝变更
```

台账进入“项目概况”；风险和问题还会成为 `blocked` 风险证据。

### 7.5 当前边界

- 不能选择负责人或编辑概率、影响、决策依据、变更影响。
- 不能添加/编辑响应计划和引用。
- 变更底层支持批准、应用和重开，但 UI 在分析后只提供拒绝。
- 决策底层支持 supersede，UI 没有入口。
- 操作理由由前端生成，用户不能填写真实治理理由。

## 8. 交付验收

页面标题是“交付物、评审、会签与验收”。

### 8.1 作用

管理交付物草稿、不可变版本、评审轮次、必签成员和验收结论。

### 8.2 创建、目录与详情

创建字段：交付物标题（最多 160 字）、摘要（最多 2,000 字）、到期日期。

目录显示标题、当前状态和聚合版本，并可 REST 校准。详情显示：

- 当前状态和聚合版本
- 不可变版本数量
- 评审轮次数量
- 版本标签、物料数量和提交时间
- 评审状态、会签数和法定人数
- 验收结论

### 8.3 业务顺序

```text
draft → 提交不可变版本
submitted → 选择必签成员 → 发起评审
reviewing → 必签人同意会签 → 关闭评审
reviewed → 记录验收通过
accepted
```

推荐按这个顺序操作：创建交付物、提交版本、选择必签人、发起评审、分别会签、满足法定人数后关闭评审、记录验收。

结果进入“项目概况”的待验收、驳回交付和健康信号，也会成为 `quality` 风险证据。

### 8.4 当前边界

- 没有负责人、计划、里程碑或台账关联控件。
- 没有真实物料选择或上传控件；提交版本会写入一个示例外部证据地址，这是占位行为。
- 版本标签、说明和评审检查项由前端生成，不能编辑。
- 只提供同意会签，且按钮可能对非必签人显示，最终由服务端拒绝。
- 验收只提供通过，底层的拒绝未接入。
- 没有归档、恢复、撤回版本和重新评审入口。

## 9. 跨空间关系

### 9.1 作用与前置链路

在两个空间之间定义允许的事项关系，并通过双方确认建立规范关系。

```text
设置中的跨空间授权 Grant
→ 关系策略
→ 双方确认
→ 选择两个工作项
→ 目标空间接受建链
→ canonical relation
```

开始前必须满足：

1. “设置 → 自动化与协同 → 跨空间授权”已有 active Grant。
2. Grant 包含 `relate`；解析最小引用还需要 `reference`。
3. 两侧任务模板都有完整发布版本。
4. 两侧工作项存在且版本正确。
5. 操作者拥有相应事项的 `relate` 或 `accept_link`。

### 9.2 关系策略

新建字段：

- 生效 Grant ID
- 关系 key
- 方向：源到目标、目标到源、双向
- 源类型 ID 和源定义版本 ID
- 目标类型 ID 和目标定义版本 ID

生命周期：

- `draft`：请求双方确认。
- `requested`：源、目标空间分别确认能力。
- `active`：可以选择端点建链、解析最小引用、暂停或撤销。
- `paused`：可以恢复。
- `revoked`：可以归档。

暂停、撤销和归档需要治理理由。

### 9.3 建链意图与最小引用

建链时填写源工作项 ID/版本和目标工作项 ID/版本。源空间发出意图后，目标空间可以接受并原子建链，也可以拒绝；源空间可以取消。拒绝和取消要求理由。

输入对端工作项 ID 后，“最小引用”只返回安全引用、类型、当前版本和是否可建链，不返回对端标题、状态或完整路径。

成功后可在有权限的工作项“事项关系”看到规范关系；该 canonical relation 也是跨空间同步的前置条件。

### 9.4 当前边界

- Grant、类型版本和工作项都需要手工填写 ID，没有选择器。
- disabled 时某些按钮可能仍可点击，最终由服务端拒绝。
- 策略和意图的截断标志没有展示。
- 理由输入缺少前端最小长度校验。
- 页面没有 canonical relation 明细目录或撤回入口。

## 10. 跨空间同步

### 10.1 作用与前置链路

基于已经建立的跨空间关系，把源工作项字段或状态变化同步到目标，并治理版本冲突。

```text
active Grant
→ active 关系策略
→ active canonical relation
→ 同步规则
→ 双方确认
→ 执行
→ 成功或冲突治理
```

字段同步需要 `read_fields` 和 `sync_fields`；状态同步需要 `sync_state`。双方管理员必须确认，并提供源、目标工作项当前版本。

### 10.2 新建规则

字段：

- 规则名称
- 授权 ID
- 关系策略 ID
- 规范关系 ID
- 方向：来源到目标、目标到来源、双向
- 来源字段
- 目标字段

当前新建规则固定为手工触发、一个字段映射、`copy` 转换、无状态映射和手工冲突策略。

### 10.3 生命周期、执行和冲突

- `draft`：请求确认。
- `requested`：来源确认、目标确认。
- `active`：执行或暂停。
- `paused`：恢复。

执行时填写方向、来源版本和目标版本。最近运行显示状态、方向和创建时间。

开放冲突可以选择：

- 跳过
- 补偿
- 死信

每次处理必须记录治理理由。版本不匹配不会静默覆盖，而会产生冲突或失败。

成功同步会更新目标工作项字段或状态，运行和冲突进入“跨团队全景”。

### 10.4 当前边界

- 页面标题包含状态同步，但当前 UI 只能配置一个字段复制映射。
- 不能编辑已有规则。
- 服务端的 revoke/archive 尚无 UI。
- `retry`、`source_wins`、`target_wins` 等策略尚无 UI。
- 两端当前版本需要手工输入。
- 本页与“设置 → 自动化与协同 → 跨空间同步”复用同一个组件和同一份数据，不是两套规则。

## 11. 跨团队全景

### 11.1 作用

把跨空间授权、关系策略、同步规则和同步冲突汇总成只读协作全景。

### 11.2 页面内容

健康统计：

- 授权数
- 关系策略数
- 同步规则数
- 待处理冲突数
- `healthy`、`attention` 或 `unknown`

事实列表按 grant、relation、sync、conflict 显示状态、版本、来源和观察时间。个人可以切换紧凑视图。

健康判定：

- 存在开放冲突：`attention`。
- 没有开放冲突但数据被截断：`unknown`。
- 其他情况：`healthy`。

发现开放冲突后，应返回“跨空间同步”处理。`cross_space_panorama` 类型的数据源还可以供结果指标读取。

### 11.3 当前边界

- 后端返回审计条目，页面目前只显示 lineage 说明，没有真正列出审计记录。
- 个人偏好底层包含 1–90 天窗口，UI 只能切换紧凑模式。
- 截断只通过 `unknown` 间接表示，没有独立告警。
- 没有手工 REST 校准按钮，只会在重新在线或窗口聚焦时刷新。

## 12. 结果指标

页面标题是“图表、看板与跨空间数据源”。它与“设置 → 度量治理 → 看板配置”复用相同组件和数据。项目管理入口偏向查看结果，但当前也会显示同样的编辑按钮。

### 12.1 前置条件

- 先在“设置 → 度量治理 → 指标定义”发布指标。
- 使用保存视图时，先创建有效视图。
- 使用跨团队全景时，先建立授权、关系和同步事实。
- 每个来源都会按当前用户重新鉴权，不复制来源权限。

### 12.2 看板目录和配置

目录显示名称、状态和空间共享/私有配置。

字段：

- 看板名称和永久 key
- 治理说明
- 图表名称和图表 key
- 可视化：table、metric_card、line、bar、stacked_bar、distribution
- 数据源：work_item_query、saved_view、cross_space_panorama
- 不可变指标版本
- 来源空间 ID
- 保存视图 ID
- Series/Point 维度，最多 2 个
- 安全钻取

当前空间 ID 会自动加入来源。

### 12.3 动作和结果

动作：保存草稿、发布不可变版本、空间共享/撤销共享、REST 重新计算、新建看板、恢复旧草稿。

结果显示：

- 看板结果状态、观察时间和诊断
- 图表名称、类型和状态
- 样本数、Series/Point、指标值
- 是否可安全钻取
- freshness、truncation 和来源诊断

证据不完整时，不显示 series、facet、数量和来源版本。

配置顺序是：发布指标 → 新建看板 → 选版本和来源 → 配图表/维度 → 保存 → 发布 → 按需共享 → 重新计算。

当前没有面向普通成员的共享看板消费入口，因为普通成员看不到项目管理主 Tab。

### 12.4 当前边界

- 编辑器只支持一个数据源、一个图表和固定布局。
- 选择 `saved_view` 时，保存视图 ID 没有变为条件必填。
- 来源空间需要输入 UUID，没有选择器。
- disable、revise、archive 等底层动作未接入。
- “私有配置”目录当前没有严格按创建者在 foundation 中过滤。
- disabled 时按钮可能先允许点击，再被服务端拒绝。

## 13. 指标风险

页面标题是“延期、阻塞、质量与资源风险”。它与“设置 → 度量治理 → 风险策略”复用相同组件和数据。

### 13.1 作用和来源

使用项目计划、台账、交付和资源等当前受权事实生成自动风险信号。风险信号不修改来源事实、不授予权限，也不用于个人绩效评价。

当前接通的主要证据：

| 信号 | 来源 |
| --- | --- |
| `overdue` | 项目计划的逾期里程碑 |
| `blocked` | 开放问题和高风险台账 |
| `quality` | 待验收或驳回交付物 |
| `resource` | 资源超载或冲突 |
| `stagnation` | 项目健康中的阻塞、停滞或严重信号 |

### 13.2 策略

目录显示策略名称、状态和发布版本。字段：

- 策略名称
- 永久 key
- 来源与解释
- 信号类型：overdue、due_soon、stagnation、blocked、quality、resource
- 严重度：info、warning、critical
- 冷却小时：1–720

动作：保存策略草稿、发布不可变策略、评估当前受权事实、新建策略、恢复旧草稿。

### 13.3 信号治理

每条信号显示类型、严重度、状态、策略版本、观察时间、证据数量和指纹，以及来源类型、版本和解释。

状态可能是 open、acknowledged、suppressed、closed、invalidated。owner/admin 可以确认、关闭、抑制或重开。

推荐顺序：先维护项目事实 → 保存并发布策略 → 评估 → 展开证据 → 治理信号。

### 13.4 当前边界

- `due_soon` 可选，但当前证据解析器不会产生这一类证据。
- 没有策略停用、恢复、归档入口。
- 信号治理原因由前端固定，不能填写实际处理说明。
- disabled 时部分按钮可能由服务端最终拒绝。
- 截断后没有继续翻页。

## 项目管理的完整数据关系

```text
工作日历 + 工作项估分
  ├─ 时间投影
  └─ 与已提交工时计算估算偏差

人员分配 + 工作日历 + 已提交工时
  ├─ 资源负荷
  ├─ 资源日程甘特
  └─ 资源风险证据

项目计划 ──→ 项目概况 ──→ 逾期风险证据
风险/问题/决策/变更 ──→ 项目概况 ──→ 阻塞风险证据
交付与验收 ──→ 项目概况 ──→ 质量风险证据

跨空间授权
  → 关系策略
  → canonical relation
  → 同步规则
  → 跨团队全景
  → 结果指标数据源

已发布指标 → 结果看板 → 当前受权结果
项目事实 → 风险策略 → 自动风险信号
```
