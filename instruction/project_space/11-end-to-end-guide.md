# 从零配置到日常使用

本章把前面的页面说明串成一条可执行路径。第一次落地时，建议先让一个简单任务模板完整跑通，再扩展高级流程、跨空间同步和度量。

## 阶段 1：确定空间边界

负责人先回答：

- 这个空间负责什么业务结果？
- 哪些团队和用户需要进入？
- 哪些数据不应放入这里？
- 普通成员和访客分别需要看到什么？
- 需要空白起步，还是参考场景模板？

然后创建空间，填写稳定的名称、编码、可见性和说明。

验收点：

- 公共头部显示正确空间和 owner 身份。
- private/workspace 的发现范围符合预期。
- 没有把“可发现”误当成“可查看内容”。

## 阶段 2：建立成员和职责

进入“成员 → 空间成员”：

1. 保留一位明确 owner。
2. 给需要配置和治理的人 admin。
3. 日常执行者使用 member。
4. 受限协作者使用 guest。
5. 优先使用“直接加入”；使用邀请前确认收件闭环可用。

验收点：

- owner/admin 能看到项目管理、成员和设置。
- member/guest 只看到概览和工作项。
- 角色变化后重新加载导航符合预期。

## 阶段 3：选择或创建任务模板

进入“设置 → 工作模型”：

1. 检查系统基础模板或场景安装产生的模板。
2. 不需要的模板先停用，不要急于退役。
3. 需要新业务对象时新建模板，确定永久 type key。
4. 为模板写清楚用途，避免“任务 1、任务 2”式模糊命名。

建议第一次只选一个模板，例如“任务”，完成后续全链路。

## 阶段 4：设计字段

进入当前模板的“配置字段”：

1. 列出业务必须记录的数据。
2. 选择正确类型：日期用 date/datetime，枚举用 select，人员用 user。
3. 为每个字段建立稳定 key 和清楚名称。
4. 配置默认值、选项和结构化校验。
5. 废弃选项使用停用，避免破坏历史解释。

最小测试模板可以包含：

- 标题，系统字段。
- 说明，text。
- 优先级，single_select。
- 截止日期，date。
- 负责人，user；注意当前候选目录边界。

验收点：字段详情中的类型、存储语义、选项、规则和状态正确。

## 阶段 5：设计新建页和详情页

进入“页面布局”：

1. 选择“新建页”，没有布局时从当前字段初始化。
2. 用 section/tab/column 组织字段。
3. 把创建时必须填写的字段放到新建页。
4. 选择“详情页”，放入执行过程中需要查看和维护的字段。
5. 配置 owner/admin/member/guest 的字段访问。
6. 保存后运行访问预览。

验收点：

- create 和 detail 两份布局都存在。
- 一个字段没有重复放入同一布局。
- 没有引用停用字段。
- guest 的敏感字段为 hidden 或 read，而非 write。
- 理解显示条件当前尚未在运行时执行。

## 阶段 6：配置数据权限

进入“设置 → 流程与权限”，选择同一模板。

先理解初始的 4 个空间角色、4 个事项角色和 5 条策略。最低风险的做法是：

1. 保留系统策略 key。
2. 明确 guest 是否真的需要 comment 和 field_read。
3. 明确 member 是否需要 archive/restore。
4. 对敏感动作添加范围明确的 deny。
5. 首次配置优先使用当前已接线的 space_role/work_item_role 和简单 data scope。
6. 保存权限模型草稿。

验收点：

- 没有把 priority 当成 allow/deny 冲突胜负。
- 知道任何 deny 都覆盖 allow。
- 字段访问策略没有被误当成事项授权。
- 模型显示“已同步”。

## 阶段 7：配置关系

只在业务确实需要时添加：

- 普通关联：normal。
- 工作分解：parent_child。
- 先后依赖：dependency。
- 阻塞：blocking。

为正反方向分别起业务名称，设置类型范围、基数、删除策略和最大深度。之后在布局中引用 relation key 时必须完全一致。

验收点：源类型含当前模板，目标类型明确，没有循环或不合理自关联。

## 阶段 8：选择一种流程

### 简单生命周期：状态流

适合“待处理 → 处理中 → 已完成”这类单线状态：

1. 建立恰好一个 initial 状态。
2. 建立 active、terminal/canceled 状态。
3. 建立动作并配置授权角色和必填字段。
4. 建立来源到目标转换。
5. 必要时添加声明式守卫。
6. 预览并保存到草稿。

### 审批和多人协作：节点流

适合审批、会签、分支、汇聚、交付物：

1. 从含 nodeFlow 的配置模板或已有快照起步。
2. 核对阶段、节点和连线。
3. 配置处理策略、候选角色、法定人数。
4. 谨慎编辑 JSON 高级配置。
5. 明确点击“保存节点流”。

一个模板不能同时存在 stateFlow 和 nodeFlow。

## 阶段 9：校验和发布

发布前逐块确认已保存，然后：

1. 点击“校验配置”。
2. 处理所有阻断项。
3. 阅读 warning、diff、兼容和迁移建议。
4. 对需复核/迁移的变化明确确认。
5. 发布不可变版本。

验收点：

- 草稿状态为 valid。
- 发布后模板标记 configurationReady。
- “概览 → 可用工作项”出现模板。
- 当前发布版本、哈希和时间正确。

## 阶段 10：创建并验收第一条事项

分别以管理员和普通角色检查：

1. 从“概览 → 可用工作项”打开模板。
2. 新建事项。
3. 检查 create 布局、隐藏/只读/可写/必填字段。
4. 创建后检查 detail 布局。
5. 在“状态流程”执行动作，或启动“审批与协作流程”。
6. 在“事项关系”建立测试关系。
7. 在“协作记录”评论、添加协作者、上传附件。
8. 在“权限”重新校准关键动作解释。

如果管理员能用而 member/guest 不能，不要直接改前端；先在事项“权限”页检查动作、策略来源和字段投影。

## 阶段 11：组织团队工作

进入“工作项”：

1. 选择任务模板。
2. 用表格检查基础数据。
3. 有 parent_child 时使用层级树。
4. 有状态流时使用看板。
5. 有日期字段时使用日历或甘特。
6. 保存个人视图，需要协作时分享权限。

然后在“项目管理”逐步建立：

- 项目计划和里程碑。
- 工作日历、估分和实际工时。
- 人员分配、产能和资源日程。
- 风险、问题、决策和变更台账。
- 交付、评审、会签和验收。

项目概况只汇总这些上游事实；如果上游为空，概况不会替你生成完整管理数据。

## 阶段 12：增加自动化

先从一个低风险规则开始：

1. 选择受控触发事件。
2. 配置一个简单条件和动作。
3. 保存并发布。
4. dry-run。
5. 启用并小范围执行。
6. 检查运行步骤、错误码和限额。

外部连接先做无副作用测试。秘密只使用凭据引用，不写入 URL、规则备注或工作项字段。

## 阶段 13：建立跨空间协作

只有确实需要跨空间时才配置：

```text
最小 Grant
→ 两侧确认
→ 关系策略
→ 两侧确认
→ 建立 canonical relation
→ 同步规则
→ 两侧确认
→ 带当前版本执行
→ 冲突治理
```

任何一步都不能用共享视图、共享看板或企业管理员身份代替显式授权。

## 阶段 14：度量和治理

1. 写清指标语义并发布不可变版本。
2. 看板引用明确指标版本和受权来源。
3. 重新计算并正确解释 unknown/suppressed/stale/truncated/no_sample。
4. 维护项目计划、台账、交付和资源事实。
5. 发布风险策略并评估证据。
6. 运行治理报表，核对健康和截断状态。

## 阶段 15：版本演进和存量事项

修改字段、布局、权限或流程后会发布新版本。记住：

- 新建事项使用新的 current version。
- 已有事项继续绑定旧 version。
- 回滚会创建新草稿和新发布版本，不原地切回。
- 存量状态/节点初始化只处理显式清单。
- backfill 前先发布目标版本。

不要用数据库批量改 pointer 或隐式迁移替代产品中的显式版本和批次流程。

## 阶段 16：停用或归档

结束使用前：

1. 完成或记录未结事项、工时和审批。
2. 处理自动化失败、跨空间冲突和死信。
3. 留存必要治理回执。
4. 通知成员。
5. 确保 owner 可以恢复。
6. 短期暂停用 disabled，历史封存用 archived。

## 常见问题定位表

| 问题 | 优先检查 |
| --- | --- |
| 看不到某个主 Tab | 空间角色、服务端 availableActions、空间状态 |
| 概览没有可用模板 | 模板 active、configurationReady、已发布版本、view/create |
| 新建表单没变化 | 是否真的发布；新事项是否绑定新版本 |
| 旧事项没变化 | 这是版本设计；检查显式迁移/backfill |
| 字段看不到或不能写 | 事项动作权限 + 字段访问投影 + 字段/模板/空间状态 |
| 状态动作不可用 | 动作授权、当前状态、守卫、required fields、事项版本 |
| 节点流程发布后还是旧配置 | 节点流是否单独点击保存，再校验发布 |
| 关系页为空 | 当前绑定版本是否发布关系定义 |
| 项目概况无健康数据 | 计划、台账、交付上游是否维护并校准 |
| 跨空间关系无法建立 | active Grant、operation、双方确认、版本、relate/accept_link |
| 同步冲突 | canonical relation、两端版本、Grant 范围、冲突策略 |
| 指标显示 unknown/truncated | 来源权限、预算和完整性，不要当成 0 |
| 场景模板安装后缺组件 | 当前只真实创建任务模板，其余组件需手工配置 |
