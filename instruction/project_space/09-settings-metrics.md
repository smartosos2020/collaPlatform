# 设置 → 度量治理

“度量治理”把指标口径、看板呈现、自动风险信号和治理审计放在一条可追踪链路中。

内部子 Tab 顺序：

1. 指标定义
2. 看板配置
3. 风险策略
4. 治理报表

推荐依赖顺序也是这四步：先发布指标，再创建看板；维护项目事实后发布风险策略并评估；最后用治理报表汇总配置健康。

所有结果都按当前访问权限计算。以下结果状态不能解释为数值 0：

- `unknown`：无法确定。
- `suppressed`：因安全或样本约束被抑制。
- `stale`：结果过期。
- `truncated`：只读取了预算内部分数据。
- `no_sample`：没有可计算样本。

## 1. 指标定义

### 1.1 作用

定义一个指标的永久业务语义、聚合方式、单位、维度、时间窗口和比较口径。看板引用的是已发布不可变指标版本，而不是随时变化的草稿。

### 1.2 指标目录

显示指标名称、状态和当前版本。选择后可查看草稿和发布版本信息。

### 1.3 字段

| 字段 | 作用 |
| --- | --- |
| 指标名称 | 面向使用者的名称 |
| 永久 key | 稳定标识；创建后不应改变 |
| 语义说明 | 明确“算什么、不算什么” |
| 聚合 | count、sum、average、ratio |
| 单位 | count、hours、days、percent、points |
| Measure | 被统计的度量字段或来源量 |
| 维度 | 最多 4 个，用于分组 |
| 窗口 | rolling 或 fixed |
| 长度 | 1–366 |
| 粒度 | day、week、month |
| IANA 时区 | 时间窗口解释时区 |
| 比较区间 | none 或 previous_period |

### 1.4 操作

- 保存草稿
- 发布不可变版本
- 窗口预览
- 新建指标

发布后显示发布版本、定义指纹、草稿差异和来源合同。

离线时只保存按当前账号、工作区和空间隔离的本机草稿，不会伪造服务端保存或指标结果。

### 1.5 当前边界

底层 ratio 模型需要 numeratorMeasureKey 和 denominatorMeasureKey，但页面没有这两个输入。当前不能仅靠 UI 完整构造比率表达式；选择 ratio 前应确认已有模板或接口是否提供了完整定义。

## 2. 看板配置

本页与“项目管理 → 结果指标”复用同一组件和数据。设置入口偏向配置，项目管理入口偏向使用结果；当前两处都能看到相同编辑动作。

### 2.1 前置条件

必须先有已发布指标版本。使用保存视图或跨团队全景作为来源时，还要先准备相应上游对象。

### 2.2 看板和图表字段

- 看板名称
- 永久 key
- 治理说明
- 图表名称
- 图表 key
- 可视化类型
- 数据源类型
- 不可变指标版本
- 来源空间 ID
- saved view ID
- Series/Point 维度，最多 2 个
- 安全钻取

可视化类型：

- table
- metric_card
- line
- bar
- stacked_bar
- distribution

数据源：

- `work_item_query`
- `saved_view`
- `cross_space_panorama`

### 2.3 操作顺序

1. 新建看板。
2. 选择已发布指标版本。
3. 配置来源、图表、维度和安全钻取。
4. 保存草稿。
5. 发布不可变版本。
6. 按需“空间共享”或撤销共享。
7. 点击“REST 重新计算”。

共享只共享看板配置引用，不复制指标结果、缓存或跨空间授权。

### 2.4 结果

显示：

- 整体状态、观察时间和诊断
- 图表状态
- 当前授权样本数
- series/point
- 是否可安全钻取
- freshness 和 truncation

结果未 ready 时，不展示 series、facet、数量和来源版本，避免通过错误外形泄漏隐藏数据。

### 2.5 当前边界

- 当前编辑器只支持一个数据源、一个图表和固定单格布局。
- 底层支持数组和多图表，但没有布局设计器。
- 来源空间和保存视图仍需要填写 ID，缺少完善选择器与条件必填。
- 共享看板当前没有单独面向普通成员的消费入口。

## 3. 风险策略

本页与“项目管理 → 指标风险”复用同一组件和数据。

### 3.1 作用

用已发布策略从当前受权的计划、台账、交付、资源和项目健康事实中生成风险信号。风险不会改写来源事实，不授予权限，也不形成个人绩效或隐式利用率评价。

### 3.2 策略目录和字段

目录显示名称、状态和发布版本。

字段：

- 策略名称
- 永久 key
- 来源与解释
- 信号类型
- 严重度：info、warning、critical
- 冷却时间：1–720 小时

可用信号类型包括 overdue、due_soon、stagnation、blocked、quality、resource。默认新策略选中 overdue、blocked、quality、resource。

主要证据：

| 信号 | 当前来源 |
| --- | --- |
| overdue | 逾期里程碑 |
| blocked | 开放问题和高风险台账 |
| quality | 待验收或驳回交付物 |
| resource | 超载或资源冲突 |
| stagnation | 项目健康中的阻塞、停滞或严重信号 |
| due_soon | 目录可选，但当前解析器尚未生成此类证据 |

### 3.3 操作顺序

1. 先维护计划、台账、交付和资源事实。
2. 新建或选择策略。
3. 填写类型、严重度和冷却时间。
4. 保存策略草稿。
5. 发布不可变策略。
6. 评估当前受权事实。

离线时不会伪造评估或状态变化。

### 3.4 风险信号

显示：

- 信号类型
- 严重度
- 状态
- 策略版本
- 观察时间
- 受限证据数量和指纹
- 来源类型、来源版本和解释

状态可能为 open、acknowledged、suppressed、closed、invalidated。

owner/admin 可执行：

- 确认
- 关闭
- 抑制
- 重开

当前治理理由由前端固定，不能填写真实处理说明；策略停用、恢复和归档也没有 UI。

## 4. 治理报表

### 4.1 管理驾驶舱

顶部显示：

- 已发布指标
- 活动看板
- 待治理风险
- 各组件健康状态
- 来源版本
- 当前可见数量

若任一来源被截断，会提示配置健康为 unknown，导出数量不完整。

### 4.2 报表定义

字段：

- 报表名称
- 永久 key
- 脱敏与来源说明
- 报表区块

区块可选：

- metrics
- dashboards
- risks
- configuration
- audit

按钮：

- 保存发布定义
- 运行当前受权报表

“保存发布定义”当前是一次性保存可运行定义，不采用与任务模板相同的草稿校验发布工作台。

### 4.3 审计运行与导出

运行记录显示状态、来源指纹、完成时间和 report version。owner/admin 可执行“逐行重校准导出”。

报表和导出只包含当前受权治理元数据。隐藏内容不会进入字段、数量、文件名、facet 或错误外形。

当前导出接口只返回导出记录 ID、行数、截断标志和内容哈希；前端没有真正下载 CSV 或显示完整回执，因此“导出”按钮名称强于当前可见结果。

## 5. 从事实到治理的关系

```text
任务模板发布 + 工作项事实
          ↓
指标定义（不可变口径）
          ↓
看板配置（引用指标版本）
          ↓
当前受权计算结果

项目计划 / 风险问题台账 / 交付 / 资源
          ↓
风险策略（不可变版本）
          ↓
风险信号及受限证据

指标 + 看板 + 风险 + 配置健康 + 审计
          ↓
治理报表
```

## 6. 验收建议

- 指标语义说明能让另一位管理员准确复述口径。
- 看板引用明确的发布版本，而非草稿。
- 对 unknown、suppressed、stale、truncated、no_sample 不展示 0。
- 跨空间来源已存在明确 Grant，不以共享看板代替授权。
- 风险信号能回到真实来源事实解释。
- 导出前确认当前版本只生成治理回执，不一定直接下载文件。
