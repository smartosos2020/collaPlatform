# 工作项详情

从表格、列表、层级树、看板、日历、甘特、概览待办或空间动态点击事项后，会进入工作项详情。

子 Tab 顺序：

1. 事项详情
2. 状态流程
3. 审批与协作流程
4. 事项关系
5. 协作记录
6. 权限

事项不存在或无权查看时，页面不会披露其内容，只显示“工作项不存在或你无权访问”，并提供返回列表。

## 1. 事项详情

### 1.1 顶部信息与动作

顶部显示：

- 返回列表
- 任务模板名称
- 事项编号
- 进行中/已归档

根据服务端能力显示：

- 保存：有 `edit` 时出现，离线禁用。
- 归档：有 `archive` 时出现，需要确认。
- 恢复：有 `restore` 时出现。

### 1.2 行动摘要

显示：

- 当前状态
- 负责人
- 截止时间
- 下一步动作

状态流动作以按钮呈现，点击后切换到“状态流程”；其他可用事项动作以标签呈现。

### 1.3 详情表单

表单包含标题和已发布 detail 布局中的字段。字段是可写、只读还是隐藏，由服务端字段访问投影决定。

保存带事项版本做并发控制：

- 成功后刷新服务端事实。
- 如果事项已被别人修改，当前输入会保留并提示刷新对比。
- 普通失败同样保留输入。
- 事项归档后，布局以只读方式呈现。

“设置 → 工作模型 → 页面布局 → 详情页”的新发布配置，只用于绑定新版本的新工作项；已有事项仍按创建时绑定的配置版本显示。

## 2. 状态流程

状态流程是单状态机式的事项生命周期：任意时刻只有一个当前状态，通过动作和转换推进。

页面显示：

- 当前状态
- 当前用户可执行的状态动作
- 动作要求补充的必填字段
- 状态历史

执行动作时，“事项详情”中尚未保存的字段值会作为 `fieldPatch` 一并提交。服务端校验当前状态、事项版本、动作授权、守卫和必填字段。

### 2.1 常见状态

| 情况 | 页面行为 |
| --- | --- |
| 模板未配置状态流 | 事项仍可查看，提示联系管理员 |
| 流程尚未初始化 | 不显示动作 |
| 当前没有可执行动作 | 提示当前无需用户推进 |
| 没有历史 | 显示“暂无状态历史” |
| 离线 | 保留字段输入和待重试请求，不发送命令 |
| 409 并发冲突 | 状态或事项已更新，保留输入和请求 |
| 422 校验失败 | 动作条件或必填字段未满足 |

失败重试会复用同一个请求 ID，避免重复推进。

终止动作需要确认。“终止业务流程”只改变流程状态，不等于归档工作项。

### 2.2 受控纠错

owner/admin 在 active 事项上可以执行受控纠错：

1. 输入目标状态永久 key。
2. 输入至少 10 个字符的原因。
3. 确认执行。

纠错会追加不可变历史、审计和事件，不会改写旧历史。当前入口按 owner/admin 角色显示，而不是按单独的 `workflow_manage` 能力显示，最终仍以服务端拒绝或允许为准。

## 3. 审批与协作流程

这是节点流程的运行页面，适合审批、会签、多人任务、分支汇聚和交付物处理。

页面状态：

- 未配置或返回 404：外层 Tab 仍存在，但当前组件可能显示空白。
- 已配置但未启动：显示“启动节点流”，离线禁用。
- 加载失败：可重试。
- 已启动：显示实例状态和策略版本。

启动后内部 Tab 顺序为：

1. 实例图
2. 任务
3. 历史

### 3.1 实例图

显示：

- 活动 token 当前所在节点。
- 节点状态和进入时间。
- 节点下的任务、分派策略、任务状态和截止时间。

点击任务可进入任务执行区。

### 3.2 任务

任务区可能显示：

- 节点和任务状态
- 受理人或候选池
- 候选人数
- 截止时间
- 服务端投影的可见、只读、可写字段
- 表决、提交或退回决定
- transfer 目标用户 UUID
- 交付物策略及已提交数量
- 交付物 manifest JSON
- 服务端允许的动作，例如 `complete`、`submit`、`vote`、`withdraw`、`reject`、`transfer`

交付物必须先在“协作记录 → 附件”上传，再按策略提交 `fileId/objectId`。临时上传不会自动成为节点交付物。

### 3.3 历史

显示序号、事件类型、节点 key、操作者类别和时间。

管理动作：

- 恢复：选择恢复命令，填写原因和精确确认文本。
- 升级实例：填写目标类型版本 UUID、节点映射 JSON、原因和确认文本。
- 刷新。

当前恢复和升级按钮没有按服务端单独能力在前端隐藏，普通用户可能看到入口后被服务端拒绝；部分 key、UUID、JSON 和事件名仍直接面向使用者。

## 4. 事项关系

只有事项绑定版本包含关系定义时才有实际内容；否则外层 Tab 仍存在，内部可能为空。

内部 Tab 顺序：

1. 关系
2. 局部层级
3. 影响分析
4. Legacy 承接

### 4.1 关系

展示所有当前用户可见的关系：

- 关系方向和名称
- 对端标题、编号、类型和状态

拥有编辑能力时可以：

1. 选择关系定义。
2. 搜索当前有权访问的目标工作项。
3. 建立关系。

可撤销的关系显示“撤销”，并要求至少 3 个字符的审计原因。达到展示硬限时，页面会提示按 relation key 缩小范围。

当前建立关系入口使用通用 `edit` 判断，而不是单独的 `relate`，最终以服务端鉴权为准。

### 4.2 局部层级

只使用已发布的 `parent_child` 关系。

显示：

- 关系定义选择
- 层级面包屑
- 局部树
- 子节点和兄弟节点替代列表
- 截断或降级原因

active 空间且事项可编辑时，可以调整父项，或选择任务模板、输入标题并拆解子工作项。没有父子关系定义时显示“当前发布版本没有父子关系定义”。

### 4.3 影响分析

只使用 `dependency` 或 `blocking` 关系。

选择关系定义和上游/下游方向后执行“校准”，结果显示路径深度、源事项和目标事项。不可见节点只显示“受限节点”。

如果达到节点数或深度硬限，结果只是当前受权范围内的局部影响，不代表完整关键路径、工期或自动流转结论。

### 4.4 Legacy 承接

只对 owner/admin 显示，用于把同空间旧 issue relation 承接为规范关系。

步骤：

1. 选择关系定义。
2. 填写审计原因。
3. 生成 dry-run plan 或正式 plan。
4. 查看总数、可迁移、保留、失败和 manifest。
5. 执行、续跑、Verify 或 Rollback。

非 WorkItem 目标必须保留原有语义，不能静默丢弃。当前入口按角色名显示而不是按 `migration_manage` 能力显示。

## 5. 协作记录

内部 Tab 顺序：

1. 评论
2. 参与者
3. 附件
4. 活动

### 5.1 评论

当前有 `edit` 时可以输入最多 20,000 字，点击“发布”或使用 Ctrl/Command + Enter。列表显示作者、时间和内容；无评论时显示“暂无评论”。

### 5.2 参与者

当前有 `edit` 时，可以从有效空间成员中选择尚未参与的人。新参与者固定加入为 `collaborator`。

列表显示头像、姓名、事项角色，以及 owner/assignee 的“催办”按钮。

当前页面不能移除参与者，也不能在新增时选择 assignee、watcher 等其他事项角色。

### 5.3 附件

当前有 `edit` 时可上传附件并查看进度。列表显示文件名、文件大小、上传人、上传时间和下载入口。当前不能删除附件。

### 5.4 活动

显示原始活动类型、操作者和时间，不显示活动 payload。部分活动仍以技术 key 呈现。

### 5.5 当前权限接线边界

评论、参与者和附件写操作当前统一按 `edit` 判断，没有分别按 `comment`、`participant_manage`、`attach` 隐藏入口；催办也没有单独能力判断。各查询失败没有独立错误提示，失败有时可能看起来像空列表。最终操作仍由服务端校验。

## 6. 权限

此页用于查看当前用户对当前事项的服务端能力和字段访问投影。

### 6.1 服务端能力

以标签展示当前事项的 `availableActions`；没有能力时显示“无可用动作”。常见动作包括查看、编辑、归档、恢复、删除、评论、附件、参与人管理、状态流转、流程管理、关系、字段读写、角色/策略管理、权限解释/申请、治理检查和迁移管理。

### 6.2 安全解释

1. 选择一个动作。
2. 点击“重新校准”。
3. 查看允许/拒绝、原因码、可披露策略来源和是否可申请。

解释失败不会泄漏隐藏策略或主体信息。当前 `requestAvailable` 只显示“可申请/不可用”，页面尚没有真正提交权限申请的按钮。

### 6.3 字段访问投影

按字段显示：

- 字段 key
- `read` 或 `write`
- 是否 required

被隐藏字段不会通过这个页面泄漏其值。部分动作、原因和字段模式仍使用英文技术 key。

## 7. 一个事项的推荐执行顺序

1. 在“事项详情”填写字段并保存。
2. 在“状态流程”推进轻量生命周期。
3. 如配置了节点流，在“审批与协作流程”执行审批或协作任务。
4. 在“事项关系”建立父子、依赖、阻塞或普通关系。
5. 在“协作记录”评论、添加协作者、上传附件。
6. 对任何“为什么看不到/不能操作”的问题，在“权限”中重新校准解释。
