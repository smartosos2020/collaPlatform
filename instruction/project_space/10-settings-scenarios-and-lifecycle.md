# 设置：场景模板与空间生命周期

## 子 Tab 6：场景模板

场景模板是一组跨模块组件清单，用来建立某类项目的起步结构。

它与“流程与权限 → 配置模板”不同：

| 模板 | 复用范围 |
| --- | --- |
| 配置模板 | 一个任务模板的完整已发布配置 |
| 场景模板 | 多个任务模板、流程、关系、视图、计划、自动化、指标等组件及依赖 |

创建空间时选择“研发协作/市场项目/HR 事务/交付管理”只保存引导选择，不会自动安装。真正的预检和安装在本页进行。

页面顺序：

1. 场景模板目录
2. 模板说明、版本和清单指纹
3. 组件及依赖顺序
4. 清单验证结果
5. 安装与升级
6. 执行回执和冲突

### 1. 场景详情中的字段

选择场景后显示：

- 场景 key
- 当前目录版本
- 清单指纹
- schema 版本
- 公共能力数量
- 组件数量
- 每个组件的类型、是否必需、owner contract、前置依赖
- 确定性拓扑安装顺序

目录和预览本身不授予权限。组件“必需”表示清单依赖要求，不代表当前版本已经真实创建该组件。

### 3. 清单验证

在线时会验证：

- 清单指纹。
- 组件 key 和类型。
- 依赖是否存在。
- 是否存在依赖环。
- 确定性安装顺序。

验证通过只说明清单拓扑有效，不代表每个组件已经安装或适合当前团队。

### 4. 安装与升级

#### 4.1 本地清单指纹

用于升级时表达当前本地清单版本。如果留空，页面使用场景当前 manifest hash。

#### 4.2 预检

以 dry-run 方式生成计划和步骤，不产生业务安装副作用。建议任何安装或升级前先预检。

#### 4.3 安装模板

执行前再次校准当前角色和每个 owner capability。使用幂等 request ID，同一意图可以安全重试。

#### 4.4 检查升级与冲突

比较上游、本地和当前安装状态。冲突会显示 keyPath、原因和是否解决。

“保留本地并升级”把 `local_manifest` 冲突解析为保留本地。不能把这个单一按钮理解为已经支持所有组件逐项冲突编辑。

#### 4.5 解绑引用

只解除场景上游引用，不删除已经创建的本地对象。解绑后本地对象继续存在，但不再跟踪该场景升级。

#### 4.6 执行回执

显示：

- operation 和 status
- 是否精确重放
- run ID
- 步骤数
- 本地 manifest hash
- 每一步组件、operation、owner contract 和状态
- 未决或已解决冲突

失败不会伪造成功，可以按同一意图安全重试。

### 5. 当前场景安装的真实边界

当前后端只对 `work_item_type` 组件真实创建任务模板。其他组件当前主要生成 `verify_owner_reference` 步骤并记录 completed：

- 流程
- 关系
- 保存视图
- 看板/日历
- 项目计划
- 自动化/通知
- 指标
- 风险策略
- 治理看板

因此，“场景安装成功”目前主要表示任务模板已创建、其余 owner contract 已登记和校验，不等于整套业务场景已经配置完成。

安装后必须继续：

1. 到“工作模型”检查每个任务模板的字段和布局。
2. 到“流程与权限”配置并发布流程、关系和权限。
3. 到“自动化与协同”创建真实规则和连接器。
4. 到“度量治理”创建和发布指标、看板、风险策略。
5. 到“项目管理”创建计划并验证结果。

## 管理首页 A. 基础信息：启用、停用与归档

空间生命周期不再占用独立设置子 Tab，也不再放在独立危险操作卡中。管理员在“管理首页 → A. 基础信息”的操作区处理空间整体生命周期：生命周期按钮位于“保存设置”右侧，并按服务端返回的 `availableActions` 显示。

### 6. active

空间正常运行，成员按角色和策略协作。

可以：

- 停用
- 归档

### 7. disabled

- 数据保留。
- 成员不能继续写入或调整成员。
- 管理员可以查看并恢复。

可以：

- 恢复为 active
- 归档

### 8. archived

空间作为历史记录只读保留。owner/admin 可以恢复为 active。

当前多个项目管理服务对 archived 直接拒绝读取，因此某些页可能显示加载失败，而不是真正完整只读。这是现有实现边界。

### 9. 状态转换

```text
active → disabled
active → archived
disabled → active
disabled → archived
archived → active
```

停用或归档会立即限制成员写入和治理操作，使用危险样式并要求二次确认。它们不会删除历史数据；恢复后成员可按当前角色和已发布配置继续协作。

执行生命周期动作前建议：

1. 完成未提交的工时、审批、交付和同步。
2. 处理自动化运行和死信。
3. 导出或记录所需治理回执。
4. 通知成员状态变化。
5. 确认至少一位 owner 可以恢复空间。
