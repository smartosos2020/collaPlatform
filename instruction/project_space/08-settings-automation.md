# 设置 → 自动化与协同

此页管理空间内声明式自动化、外部 HTTPS 连接、跨空间授权和同步，以及运行健康与限额。

内部子 Tab 顺序：

1. 自动化规则
2. 运行记录
3. 连接器
4. 跨空间授权
5. 跨空间同步
6. 运行与限额

自动化只接受受控目录中的事件、条件和动作，不允许运行脚本、SQL 或任意代码。任何运行和跨空间操作都会在执行时重新校准权限。

## 1. 自动化规则

### 1.1 作用

用声明式的 `Trigger → Condition → Action` 描述“发生什么事件、满足什么条件、执行哪个受控动作”。

### 1.2 规则目录

显示：

- 规则名称
- 状态
- 草稿版本
- 发布版本
- 更新时间

### 1.3 编辑字段

- 规则名称
- 触发事件
- 条件字段引用
- 条件操作符
- 条件值
- 受控动作
- 本地设计备注

条件操作符：exists、equals、not_equals、contains、gt、gte、lt、lte。

“本地设计备注”不会上传，不是规则事实或审计记录。

### 1.4 生命周期

1. 保存规则草稿。
2. 发布不可变版本。
3. 启用规则。
4. 不再执行时停用。

发布使规则定义不可变；启用决定事件到达时是否执行。仅保存草稿不会运行。

### 1.5 限制

- 条件最多 64 个节点、8 层。
- 动作最多 8 个。
- 当前可视化编辑器只编辑一个条件和一个动作，底层更复杂结构没有完整 UI。

## 2. 运行记录

### 2.1 作用

手工预览或执行已发布规则，并查看每一步结果。

### 2.2 输入和按钮

输入：

- 已发布规则
- 事件对象标识 `aggregateId`

按钮：

- 无副作用预览
- 执行受控操作
- REST 校准

只有 enabled 规则可以真实执行；dry-run 不产生业务副作用。

### 2.3 运行结果

显示：

- 运行状态
- run ID
- dry-run 标识
- 开始时间
- 每一步 action 类型、状态和稳定错误码

每次运行最多 8 个动作步骤，并按幂等请求语义避免重复副作用。

当前手工测试事件固定为 `project.work-item.changed`，payload 只包含 aggregateId 和 spaceId；页面不能构造其他事件类型的完整 payload。

## 3. 连接器

### 3.1 作用

保存受控 HTTPS Webhook 目标，并查看投递和死信。

字段：

- 名称
- HTTPS 目标
- 凭据引用，例如 `vault://...`

按钮：保存连接器、无副作用测试。

### 3.2 投递与死信

列表显示：

- 状态
- 投递 ID
- 尝试次数
- 创建时间
- 死信原因

### 3.3 安全边界

- 只允许 HTTPS。
- 禁止重定向。
- 禁止内网和元数据地址。
- 只保存凭据引用，不保存明文秘密。
- 签名值和 payload 不进入历史或错误信息。

当前页面只提供新建和测试，没有编辑、停用、删除连接器或死信重放入口。

## 4. 跨空间授权

### 4.1 作用

在两个空间之间建立最小、明确、双方确认的协作范围。Grant 不会创建成员，也不会复制任一侧权限。

### 4.2 新建字段

- 授权名称
- 目标空间 ID
- 方向：源到目标、目标到源、双向
- 最小操作范围
- 源类型 ID
- 源发布版本 ID
- 目标类型 ID
- 目标发布版本 ID

操作范围：

- `reference`：获取最小安全引用
- `relate`：建立关系
- `read_fields`：读取允许字段
- `sync_fields`：同步字段
- `sync_state`：同步状态

### 4.3 生命周期

```text
draft
→ 发起请求
→ 源空间确认 + 目标空间确认
→ active
→ 可暂停/恢复/撤销/归档
```

暂停、撤销和归档需要治理理由。任何一方尚未确认时都不能把目录预览或请求当成已授权。

### 4.4 结果去向和边界

active Grant 是“项目管理 → 跨空间关系”的第一项前置条件，之后还要建立关系策略和 canonical relation。

当前空间、类型和版本都需要手工填写 UUID，没有对象选择器。授权只描述允许的最小范围，实际建链和同步时还会再次检查工作项版本与事项级权限。

## 5. 跨空间同步

本页与“项目管理 → 跨空间同步”复用同一个组件和同一份规则/运行数据。

### 5.1 前置条件

- active Grant。
- 关系策略 ID。
- canonical relation ID。
- 双方空间确认。

### 5.2 新建字段

- 规则名称
- 授权 ID
- 关系策略 ID
- 规范关系 ID
- 方向
- 来源字段
- 目标字段

当前新建规则固定为手工触发、`copy` 转换、手工冲突策略、一个字段映射、无状态映射。

### 5.3 生命周期和执行

请求规则后由两侧确认；active 后可执行或暂停，paused 可恢复。

执行时填写方向、来源版本、目标版本。最近运行显示状态、方向和时间。

冲突可以：

- 跳过
- 补偿
- 死信

每次治理必须填写理由。版本冲突不会静默覆盖目标。

### 5.4 当前边界

- 当前只能配置一个字段复制映射。
- 不能配置自动触发、多字段映射、状态映射或转换表达式。
- 不能编辑已有规则。
- 依赖 ID 和工作项版本都需手工输入。
- 服务端的 revoke/archive 和更多冲突策略尚未接入 UI。

## 6. 运行与限额

### 6.1 运行健康

显示：

- 规则数
- 运行数
- 连接器数
- 死信数
- 健康诊断

筛选项：全部、失败、已暂停、死信。

当前运行列表过滤只完整接通“全部”和“失败”；选择“已暂停”或“死信”时可能显示空运行数，虽然死信统计卡仍单独计算。

### 6.2 限额

限额可以按以下维度出现：

- 空间
- 规则
- Actor
- Action

每项显示已用量和上限，可以暂停或恢复。暂停不会删除历史；恢复也不会把旧缓存或失败请求升级成授权。

## 7. 建议配置顺序

空间内自动化：

1. 确认触发事件和受控动作目录。
2. 保存并发布规则。
3. 先 dry-run。
4. 启用后执行小范围验证。
5. 在运行记录和限额页观察。

外部连接：

1. 准备 HTTPS 目标和秘密管理中的凭据引用。
2. 保存连接器。
3. 执行无副作用测试。
4. 查看投递和死信。

跨空间协作：

```text
创建最小 Grant
→ 双方确认
→ 项目管理中创建关系策略
→ 双方确认并建立 canonical relation
→ 创建同步规则
→ 双方确认
→ 手工执行
→ 治理冲突和限额
```
