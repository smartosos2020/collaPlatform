# PROJECT-PLATFORM-S21-M4 真人试用准备包

## 状态与边界

- 状态：仅准备，尚未开始 M4，也没有任何真人验收结论。
- 工程前置：只有 S21-M3 route-final、容量、安全和恢复结论全部为 Go 后才可开始。
- 证据边界：AI、自动化、模拟账号和代填记录不能替代研发、市场、HR、交付真人参与者。
- 数据边界：只使用合成数据；禁止录入候选人、员工、客户或渠道的真实隐私数据。
- 参与者边界：每类场景至少一名真实参与者，身份、授权范围和 consent 由主持人现场登记。

## 主持人开场检查

1. 为本次试用记录唯一 `trialRunId`、日期、主持人、应用 commit 和隔离环境标识。
2. 确认最新工程 Go、备份清单和隔离恢复演练均可追溯。
3. 为四位参与者分别创建最小权限账号；不共享账号或浏览器会话。
4. 向参与者说明任务目的、观察范围、原始反馈保存位置、退出权和隐私边界，并取得明确 consent。
5. 从已验证的合成基线创建研发、市场、HR、交付四个 ProjectSpace；记录基线校验和。
6. 在开始前验证恢复、收权、离线提示、旧 `/projects` 和 `/issues` 失败关闭。

## 统一记录合同

每位参与者的原始记录至少包含：

- `trialRunId`、匿名 participant key、场景、最小角色和 consent 时间；
- 每个任务的开始/结束时间、独立完成/失败、帮助请求次数；
- 参与者原话、困惑点、错误信息和建议，原始记录与主持人归纳分开；
- 关联 WorkItem/ProjectSpace 的 opaque id，不复制不可见内容；
- finding 的复现步骤、严重度、影响身份、owner 和工程证据链接；
- 试用结束后的收权、数据清理和环境恢复结果。

不得记录个人绩效、隐式评分、生物特征、无关屏幕内容或跨参与者比较。

## 四类真人任务脚本

### 研发

1. 创建或进入研发 ProjectSpace，识别需求、任务、缺陷、版本和迭代类型。
2. 新建需求并拆分任务，建立依赖或父子关系。
3. 将缺陷推进到关闭，验证状态、权限、活动记录和通知。
4. 将任务纳入版本/迭代并完成一次交接。
5. 打开深链、短暂离线后恢复，确认不存在旧 Project/Issue 页面。

### 市场

1. 创建活动，关联内容、素材、渠道和投放任务。
2. 上传合成素材并完成必要审批或交接。
3. 变更渠道计划，确认通知只发送给当前有权接收者。
4. 完成活动复盘和指标解释，不录入真实渠道凭据。
5. 执行深链、离线恢复和权限撤销检查。

### HR

1. 创建招聘计划和职位，使用合成候选人引用。
2. 安排面试并完成阶段流转。
3. 验证候选人敏感字段最小披露，不录入真实个人信息。
4. 完成 offer/onboarding 交接并确认撤权。
5. 执行深链、离线恢复和跨空间不可见检查。

### 交付

1. 创建交付项目，拆分任务、风险和交付物。
2. 建立评审/验收关系并完成一次状态推进。
3. 上传合成交付物，确认文件权限与审计。
4. 完成跨角色交接和验收。
5. 执行深链、离线恢复和通知检查。

## 立即停止条件

出现任一情况时停止相关场景，不继续收集“成功率”：

- P0/P1 安全、越权、隐私泄漏或不可恢复的数据损坏；
- 旧 Project/Issue 写入口重新出现；
- 参与者要求退出或 consent 无法确认；
- 隔离环境、备份或恢复基线不可验证；
- 账号共享、真实隐私数据、运维凭据进入浏览器或证据；
- 原始记录与参与者实际操作无法对应。

## 结束与清理

1. 撤销四类参与者全部临时权限和会话。
2. 删除未获保留批准的合成试用数据；保留不可变审计与批准证据。
3. 从基线或已验证备份恢复隔离环境并复核校验和。
4. 将原始记录与去重 finding 分开存放，限制访问。
5. 只有四类真人原始证据齐备、P0/P1 为零且清理完成后，才可给出 M4 人工结论。
